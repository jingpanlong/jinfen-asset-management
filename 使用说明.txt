锦纷资产管理系统 2.5.0
Windows 10 / 11，64 位

一、两个发行版本
portable\2.5.0\锦纷资产管理系统.exe：单文件程序，不需要安装 Python、Qt 或数据库驱动。
installer\锦纷资产管理系统-安装版-2.5.0.exe：安装版，创建开始菜单入口，可选择桌面快捷方式。
两个版本功能完全相同，默认共用当前 Windows 用户的本地数据库。
单文件指程序文件只有一个；数据库、配置和备份独立保存，不嵌入 EXE。
初次打开单文件时会解压运行依赖，启动可能比后续略慢。
软件暂未进行代码签名；请使用随附 SHA256 文件核对下载完整性。

二、首次使用
1. 双击 EXE，打开登录页，用户名已自动填好 owner。
2. 输入发行方提供的内置管理员口令即可进入。软件内置一个出厂固定的管理员账号：用户名固定为 owner，中文显示名「内置管理员」；口令的校验值在编译时写死，所以软件发给谁、装在哪台电脑、换用哪份数据库，这个账号都是一样的。
3. 明文口令不随软件分发，只在发行方手中；软件内不提供找回或重置，请与完整备份一并离线保存。
4. 内置账号的口令、角色与启用状态都不能在软件内修改，也不能被停用或删除；若数据库中的该账号被改动（改口令、降级、停用或被连续输错密码锁定），下次登录会自动恢复为出厂设置并写入操作审计。
5. 为同事新增账号：切到「注册」选项卡。用户名需 3～40 位，以英文字母开头，可含数字、下划线、点、短横线；密码需 10～200 位，包含英文字母和数字。用户名 owner 为内置账号保留，不能注册。
6. 其他人自己注册的账号一律是「只读用户」且立即可登录（能看不能改）；管理员身份只能由内置管理员账号在「账号与权限」里授予。
7. 建议依次创建部门、员工、供应商，再新增或导入资产。
8. 内置管理员账号的完整说明见 2.4高级权限使用说明.txt 第零节。

三、已实现的业务模块
总览：资产数量、在用闲置维修统计、类别分布、资产原值净值、采购待办、逾期未还及保修提醒。
资产台账：新增、编辑、搜索、状态类别筛选、序列号、所有权归属、位置、购入信息、供应商、保修信息。
资产图片：新增 / 编辑资产弹窗和资产详情均可选择上传或拖动上传图片；台账单元格也支持直接把图片拖到某一行上传。
界面响应：后台处理数据时鼠标显示等待状态；打开弹窗、详情或提示框时不会显示等待光标，弹窗内可正常查看和操作。
资产流转：领用、归还、员工调拨、位置移动、送修、维修完成、管理员报废。
使用历史：每次变化记录账号、时间及原文；原表使用人1～8可导入为历史，不限制后续追加条数。
员工部门：员工编号、部门、电话、邮箱及在职状态；在用资产未归还前不允许停用员工。
供应商：编号、名称、联系人、电话及备注。
维修：送修形成工单，完成填写结果及实际费用，保留维修起止时间。
采购：提交预算及理由，另一名管理员审批，批准后实际入库。禁止申请人审批自己的申请。
盘点：按全部资产或位置建立快照，登记实盘数量、差异说明，全部登记后关闭盘点，导出明细。
财务统计：以单价、数量、购入日期、使用月数、残值率计算直线法完整月折旧。
标签：生成资产二维码 PNG，打印资产标签或保存为 PDF。
报表：各列表支持 Excel、CSV 导出，打印和 PDF 输出。
账号：内置管理员（出厂账号 owner）唯一可授予管理员 · 注册即只读 · 角色分配 · 启用停用 · 密码更改 · 管理员重置密码 · 解锁 · 内置账号自动恢复。
安全：密码使用 PBKDF2-SHA256 哈希；连续 5 次密码错误锁定 15 分钟；修改权限由业务层复查；内置管理员账号的文件内哈希为出厂固定值，不受数据库改动影响。
密码输入：登录、注册、修改密码、重置密码、数据库连接密码等所有密码框，右侧均带「小眼睛」按钮，点击可切换显示 / 隐藏，避免输入错误。
表格显示：全部列表与弹窗表格的表头标题和数据统一居中显示，权限矩阵中的复选框与下拉框也在单元格内居中，列宽自适应内容，观感整齐一致。
审计：登录、资料修改、资产流转、采购、盘点、备份恢复均写入审计。
数据：Excel / CSV / 旧网页 JSON 导入；完整桌面 JSON 备份恢复；管理员当天首次启动自动备份。
局域网共享：管理员电脑作为主机，同一局域网内的其他电脑填入主机地址、端口和访问口令即可共用同一份数据，免安装数据库；主机会显示在线客户端与连接日志。
增删改查：资产、员工、部门、供应商、采购、维修、盘点、待办、账号、附件均支持新增、查看、修改、删除，删除受引用检查保护。

四、业务规则
领用按整条台账处理。一条资产数量为 10，则办理领用会同时领用这 10 件。
电脑等需要单独跟踪的设备，请每台分别编号；本版不提供一条台账的拆分领用。
盘点数量差异不会自动覆盖台账。请核实差异后，由有权限的操作人员单独编辑资产数量，保留修改历史。
报废仅管理员可办理，报废后不可编辑或再次领用，保留完整历史。
资产编辑及流转使用版本检查，其他客户端已经修改时要求刷新后重试。
金额以分存储，避免二进制浮点误差。
折旧仅作管理估算，不代替财务凭证；已报废资产管理净值显示为 0。
二维码内容是资产标识 JSON，用扫码器输入编号可在搜索框检索；软件不包含摄像头扫码模块。
不会自动发送邮件、短信或联网通知。提醒在总览显示。
台账和记录支持删除，但采用安全删除：只有未被任何记录引用的数据才能删除，存在流转、维修、附件、盘点、采购或待办引用时会被拒绝并说明原因。已经使用过的资产请改用「报废」保留完整历史。详见 2.6增删改查使用说明.txt。
流转记录、操作审计、导入履历属于留痕数据，仅管理员可删除；删除动作本身也会写入操作审计。

五、本地数据
默认数据库：%LOCALAPPDATA%\QiyunAssets\assets.db
连接配置：%LOCALAPPDATA%\QiyunAssets\connection.json
自动备份：%LOCALAPPDATA%\QiyunAssets\backups
诊断日志：%LOCALAPPDATA%\QiyunAssets\application.log
可在登录页“配置本地存储 / 数据库连接”选择其他 SQLite 文件。
关闭软件后可复制 SQLite 文件；软件运行时请使用“创建完整备份”，避免遗漏 WAL 中的提交。
本地 SQLite 适合一台电脑使用，不要把 SQLite 文件放到共享盘供多台电脑同时操作；多台电脑共用数据请使用第六节的局域网共享。
局域网共享设置：%LOCALAPPDATA%\JinfenAssets\share.json（访问口令以 Windows DPAPI 加密保存，不是明文）。
安装版卸载不删除公司数据库、配置及备份。

六、局域网共享（同一网络免安装数据库）
管理员电脑作为主机，其他电脑不需要安装 PostgreSQL，只要在同一个局域网内填入主机地址、端口和访问口令，即可共用同一份数据。
开启方式（主机）：用管理员账号登录 → 模板与数据管理 → 局域网数据共享 → 设置访问口令（至少 8 位）→ 开启共享 → 复制连接信息发给同事。
连接方式（其他电脑）：登录页「配置本地存储 / 数据库连接」→ 存储方式选「局域网共享主机」→ 填写主机地址、共享端口和访问口令 → 测试连接 → 保存并连接，然后用主机上已有的账号登录。
主机会显示本机可用地址、在线客户端数量和每台客户端执行的语句数；数据只在主机电脑上，不经过任何第三方服务器。
主机电脑必须开机并保持本软件运行；主机退出或关闭共享时，其他电脑立即无法读写，本机数据不受影响。
所有读写由主机排队执行：多台电脑同时保存时后到的请求会等待，等待过久会提示稍后重试。
首次开启时 Windows 防火墙会弹出提示，请选择「允许」；也可手动放行所选端口（默认 8765）。
访问口令通过挑战应答校验，口令本身不会明文经过网络；口令以 Windows DPAPI 加密保存在主机本机。
客户端与主机功能完全一致，可查询、新增、修改、删除、导入、导出、备份和恢复；任何一台电脑都能把整库备份带走，请只把口令告诉可信的同事。
主机是单点，请设置每日自动备份并把备份复制到其他位置。
公网访问（可选，默认关闭）：异地同事无法连局域网时，主机可勾选「允许公网访问」；口令强制至少 12 位，软件会探测并显示公网出口 IP，还需在路由器把端口映射到主机。同一地址口令连续错 5 次会被暂停连接 10 分钟。详细说明见 2.7 使用说明第四节。
详细步骤、限制与常见问题见 2.7局域网共享使用说明.txt。

七、PostgreSQL 数据库共享
本版支持 SQLite 和 PostgreSQL，不包含 MySQL / SQL Server 连接。
需要自行准备 PostgreSQL 服务器、专用数据库和有业务表读写权限的连接账号。
登录页配置：存储方式 PostgreSQL → 服务器、端口、数据库名、数据库用户名和密码 → 测试连接 → 保存并连接。
第一次连接会在所选数据库创建业务表和索引，请使用专用数据库，不要使用已有其他业务表的数据库。
其他电脑配置相同数据库即可共享账号、资产及所有业务记录。
SSL 默认 require，验证服务器身份请选择 verify-full 并安装 PostgreSQL 根证书；密码使用 Windows DPAPI 加密保存。
外部数据库不可连接时会显示配置提示；不会悄悄切换成本地数据库。
此软件直接连接数据库。应用角色用于受控客户端内的权限限制；数据库管理员 / 持有数据库凭据的人可直接访问数据。
如需面向不受信任的客户端、互联网开放或强制服务器端权限隔离，应增加 API 服务与独立认证，当前版本未包含该架构。
数据库服务端的维护、网络规则、证书和灾难恢复由数据库管理员配置。

八、导入与迁移
1. 数据管理中下载 Excel 模板。
2. 支持 .xlsx、UTF-8 CSV、上一版网页系统导出的 JSON；不直接支持旧 .xls。
3. 编号唯一；单价以元填写；残值率以百分比填写，如 5 表示 5%；日期 YYYY-MM-DD。
4. 新版导入支持仅新增或按编号新增 / 更新。存在非法数据时整批不提交；更新模式保留资产状态和领用关系，空白基础字段会覆盖旧值。
5. 原表使用人列保存为历史原文，显示时间是导入时间；不猜测原文里的姓名和日期。
6. 新资产导入状态为闲置，旧使用状态或人员保留在备注 / 历史；更新现有资产时保留现有状态。请核对后正式领用到员工档案。
7. Excel 单元格有文本长度限制，完整历史长期归档请使用 JSON 备份。
8. 迁移本地至 PostgreSQL：源库管理员完整备份 → 退出 → 配置目标数据库 → 连接后自动创建业务表与内置管理员账号 → 登录 → 恢复完整备份。恢复完成后账号以备份内容为准，目标库中原本的账号会被备份中的账号替换（内置管理员账号会自动补齐）。
9. 恢复会替换目标全部业务表和账号；先自动备份目标当前数据，然后恢复，完成后用源备份的账号重新登录。
10. 备份包含账号密码哈希及公司资料，不是加密归档，请放到权限受限的目录。
